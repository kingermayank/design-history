Visual git history · v0.1

Your interface has a past. See every version of it.

Figma keeps every version on an infinite canvas. Your codebase throws the old ones away. design-history takes a screenshot of every commit, past and future, and lets you travel back and forth through your UI's evolution.

$npx design-history init

Backfill the past

Point it at a repo with months of history. It replays every commit and screenshots each version, reconstructing a timeline you never recorded.

Capture the future

A non-blocking git hook screenshots every new commit in the background. Your history keeps growing without you thinking about it.

What happens when you add it

Five steps from install to time travel.

No dashboard to configure, no account to make. Everything lives in a local .design-history/ folder next to your code.

01

Install & initialize

One command scaffolds a config, installs a background commit hook, updates your .gitignore, and detects your framework for the in-app button.

$ npm i -D design-history
$ npx design-history init
# ✓ wrote design-history.config.js
# ✓ detected framework: Next.js
02

Point it at your app

Set your dev-server URL and the routes you care about. No port flags: it reads the URL your dev server prints, whatever framework you're on.

// design-history.config.js
devServer: 'http://localhost:5173',
routes: [{ path: '/' }, { path: '/pricing' }],
~30 seconds
03

Reconstruct your history

Backfill replays every past commit through one long-lived dev server, hot-swapping the source underneath it. Versions get captured, oldest to newest.

$ npx design-history backfill
[41/72] ca39808 → capture ✓
[42/72] 0103e87 → capture ✓
~2–4s per commit · a few minutes total
04

Then it just runs

From now on, every git commit fires a screenshot in the background. It never blocks your commit, and non-visual commits are quietly collapsed.

zero ceremony · fully automatic
05

Scrub through time

Open the viewer, or click the floating button in your dev app. Drag the dial and watch your interface morph across versions.

$ npx design-history view

Two ways to look back

A full-screen studio, or a button in your app.

The standalone viewer

npx design-history view opens a local studio: the big frame up top, the time-travel dial below.

  • Scrub with the dial, arrows, or ← → keys
  • Switch routes and mobile / desktop
  • See the code diff and restore any version

The in-app button

A floating button in your running app: Next.js, Vite, Remix, CRA, any framework. Click to expand the same dial over your live screen.

  • Next / React: <DesignHistory /> · Vite: one-line plugin
  • Dev-only: nothing ships to production
  • Shadow-DOM isolated: never touches your styles

What to expect · the honest version

Reconstructing history is real work.

~2–4s
per commit to capture, after first boot
~5min
a typical repo's full backfill, cache warm
100%
local: no cloud, no account, no telemetry
The first backfill takes a few minutes.

Most time is npm install where your lockfile changed. A copy-on-write cache keeps repeats fast.

Some old commits won't build, and that's fine.

Dependency drift or a broken WIP commit is logged and skipped; the run keeps going.

Non-visual commits are collapsed.

Docs, tests, config-only diffs are marked "no visual change" so the timeline stays all signal.

Dynamic routes need a stable URL.

If a page's URL scheme changed over time, older commits may show a not-found page. That's accurate history, not a bug.
